WHAT IS ZERRA?
--------------
Zerra is a zero-trust authorization platform (codenamed SENTRA) designed to
protect APIs, services, AI agents, and MCP servers. Instead of only checking
"who is making a request," SENTRA checks whether a request SHOULD happen right
now — analyzing identity, behavioral context, and request sequences in real time.

Core idea: Authorization that understands intent, not just credentials.

1. PYTHON SECURITY INTELLIGENCE LAYER  (agent/)
------------------------------------------------------------------------

A. Intent Graph Engine  (agent/graph/)
   - Maintains a NetworkX multi-relation graph: identity <-> object <-> endpoint <-> tenant
   - Detects: novel object access, rapid fan-out, cross-tenant blast radius,
     temporal edge decay
   - Returns: graph_risk_score (0.0 to 1.0) + deterministic evidence
   - Files: graph_store.py, models.py, scoring.py, explain.py,
            config.py, store.py, temporal.py + signals/ sub-module

B. Sequence Intent Scorer  (agent/sequential/)
   - Maintains bounded, per-identity sliding request windows
   - State-machine detectors for attack chains:
       enumerate -> read -> export (data exfiltration pattern)
       Credential probing (repeated 401/403 response sequences)
       Agent / MCP scope-contract violations
   - Returns: sequence_risk_score, matching pattern, triggering call index,
              feature evidence, timing metrics
   - Files: scorer_service.py, feature_extractor.py, state_machine_scorer.py,
            window_manager.py, models.py, ensemble.py, config.py,
            metrics.py, ml_scorer.py + patterns/ sub-module

C. Trust Score Engine  (agent/trust/)
   - Combines multiple risk signals into a single continuous score (0 to 100):
       graph_risk_score     (from Intent Graph Engine)
       sequence_risk_score  (from Sequence Scorer)
       authentication weakness (weak auth method penalty)
       sensitive field exposure (reading PII/financial fields)
   - Features: EWMA smoothing, warm-up protection, hysteresis,
     configurable weights (weights.py / thresholds.py)
   - Maps score -> verdict:  allow | step_up | block
   - Files: schema.py, score_store.py, dynamics.py, explain.py, inputs.py,
            models.py, publisher.py, config.py, store.py, thresholds.py, weights.py

D. Orchestrator  (agent/orchestrator/)
   - Wires together:  graph -> sequence -> trust  in one evaluation pipeline
   - Accepts a CallEvent, returns one DecisionResponse per request
   - Files: engine.py

E. Supporting Modules  (agent/)
   - contracts/              Shared Pydantic data contracts:
                               Identity, CallEvent, RiskCard, Policy, DecisionResponse
   - identity/               Identity registry and Agent Firewall
   - policy/                 Structured policy engine
   - risk_cards/             Risk Card builder (explains every block decision)
   - metrics/                Live metrics store (counts, rates, event feed)
   - attack_sim/             Attack simulator for demo scenarios
   - mock_data/              In-memory multi-tenant protected data (invoices, users, admin export)
   - reports/                Report generation
   - policy_recommendations/ Auto-recommendation engine
   - llm/                    LLM integration layer
   - agents/threat_hunter.py Threat Hunter agent

F. API Server  (agent/api.py)
   Exposes inference via FastAPI (uvicorn). Endpoints:
       POST  /v1/evaluate                  Evaluate a CallEvent, get a decision
       GET   /v1/metrics                   Live metrics snapshot
       GET   /v1/risk-cards                All Risk Cards emitted
       GET   /v1/identities                All tracked identities + trust scores
       POST  /v1/identities/{id}/revoke    Kill-switch: block an identity
       POST  /v1/identities/{id}/restore   Restore a revoked identity
       GET   /demo/invoices/{id}           Protected demo endpoint
       GET   /demo/users/{id}              Protected demo endpoint
       GET   /demo/admin/export            Protected demo endpoint

G. Demo Runner  (agent/main.py)
   - Runs a deterministic security demonstration
   - Seeds demo identities (human, agent, rogue-agent)
   - Simulates legitimate traffic, cross-tenant attacks, scope violations,
     and invoice enumeration sequences
   - Prints verdicts and Risk Card evidence to console

2. GO BACKEND / GATEWAY  (backend/)
------------------------------------------------------------------------

A. Dynamic Reverse Proxy  (backend/internal/adapters/proxy/)
   - Accepts incoming requests on port 8080
   - Extracts subdomain from the request Host header
   - Looks up the subdomain in PostgreSQL -> gets upstream api_base_url
   - Proxies the request server-side (browser never sees the upstream URL)
   - Rewrites upstream redirect Location headers back to gateway host
   - Sends correct Host header to upstream (Vercel-compatible)
   - Retains original host in X-Sentra-Original-Host for diagnostics

B. SENTRA Inference Integration
   - When SENTRA_INFERENCE_ENABLED=true:
       Every proxied request is sent to the Python inference service first
       step_up / block decisions returned by gateway (no upstream call)
       allow decisions forwarded to the upstream normally

C. Subdomain Registration API  (backend/internal/features/subdomain/)
   POST  /api/v1/proxy
   Body: { "subdomain": "qroasis", "api_base_url": "https://my-deployment.vercel.app" }
   Stores the mapping in PostgreSQL for dynamic upstream registration

D. Container Management API  (backend/internal/features/container/)
   - handler.go, service.go, repository.go, router.go, models.go
   - Manages container/sandbox lifecycle

E. PostgreSQL Schema  (backend/migrations/)
   - Table: proxy(id, subdomain, api_base_url, created_at, updated_at)

F. Security Scanner  (backend/scanner.Dockerfile)
   - Separate Dockerfile for a security scanner service

4. INFRASTRUCTURE  (compose.yaml / docker/)
------------------------------------------------------------------------

Docker Compose stack models the full local traffic path:

  Client request (Host: qroasis.gateway.test)
    -> Go gateway  :8080
    -> Python SENTRA inference  :8000
    -> allow  -> private protected upstream  :8001
    -> block / step_up  -> Risk Card returned, no upstream call
    -> Frontend dashboard  :3000  reads metrics, identities, Risk Cards

Services defined:
  Go backend gateway, Python SENTRA inference API,
  Protected upstream demo service (no public port),
  Next.js frontend dashboard, PostgreSQL database

================================================================================
  HOW TO RUN
================================================================================

Python inference only:
  uvicorn agent.api:app --host 127.0.0.1 --port 8000
  python -m agent.main

Go backend only:
  cd backend
  go run ./cmd
  (requires PostgreSQL + DB_CONN_STR env var)

Frontend only:
  cd frontend
  npm install
  npm run dev
  -> http://localhost:3000

Full stack (Docker):
  docker compose up --build -d
  python tests/e2e_pipeline.py
  docker compose down -v
